# T02 - Strings and localization

## Goal
Convert the Android `strings.xml` (en + ar) into ARB files with a small repeatable Dart script, wire up
`flutter gen-l10n`, and make the app able to switch between Arabic (default, RTL) and English. Every later screen
uses these strings, so this comes before any UI.

## Read first
- `app/src/main/res/values/strings.xml`, `app/src/main/res/values-ar/strings.xml`
- `app/src/main/java/com/alalmiya/lavender/utils/utilities/CommonUtils.kt` (`changeLanguage`)
- `app/src/main/java/com/alalmiya/lavender/base/ParentActivity.kt` (locale applied on create, default "ar")
- `docs/migration/CONTEXT.md` §9 (Strings), §6.1 (APP_LANGUAGE default "ar")
- `docs/migration/PLAN.md` §4.6

## Build
- `lavender-flutter/tool/strings2arb.dart` — converter script.
- `lavender-flutter/lib/l10n/app_en.arb`, `app_ar.arb` — generated by the script (committed).
- `lavender-flutter/l10n.yaml`.
- `lavender-flutter/lib/core/l10n/l10n_ext.dart` — `extension L10nX on BuildContext { AppLocalizations get l10n => AppLocalizations.of(this)!; }`.
- `lavender-flutter/lib/app.dart` — localization delegates, supported locales, locale `ar` for now.
- `lavender-flutter/test/tool/strings2arb_test.dart` — tests for the conversion functions.

## Steps
1. `flutter pub add flutter_localizations --sdk=flutter` and `flutter pub add intl`; `flutter pub add --dev xml`.
   In `pubspec.yaml` under `flutter:` add `generate: true`.
2. Write `tool/strings2arb.dart` (pure Dart, run with `dart run tool/strings2arb.dart`). Put the conversion logic in
   top-level functions so the test can import them (`import '../../tool/strings2arb.dart';` works from `test/tool/`).
   - Input paths: `../lavenderk/app/src/main/res/values/strings.xml` and `../lavenderk/app/src/main/res/values-ar/strings.xml` (relative to `lavender-flutter/`).
   - Parse with `package:xml`. Take only `<string>` elements; **skip** `translatable="false"` and skip `<array>`/`<string-array>`.
   - Key: Android name → lowerCamelCase (`good_morning` → `goodMorning`, `doctorM` stays `doctorM`). If the result is a
     Dart reserved word or starts with a digit, append `Text`. If two names collide, append `2` to the second and print a warning.
   - Value: use the element's full text (CDATA included), then: trim; replace `\'`→`'`, `\"`→`"`, `\n`→newline, `\@`→`@`, `\?`→`?`;
     replace `%%` with a single `%`.
   - Placeholders: regex `%(\d+\$)?(\d+)?([sd])`. Number them in order of appearance unless an explicit `N$` index is given
     (`%1s/%2s` means width 1/2 — treat as sequential args 1 and 2). Replace each with `{pN}`. Record metadata
     `"@key": {"placeholders": {"p1": {"type": "String"}}}`. Use type `String` for every placeholder, also for `%d`
     (call sites pass `.toString()`, exactly like the Android code does).
   - Escape literal `{` / `}` that are not placeholders by wrapping in single quotes is NOT needed if none exist; the script must
     print a warning listing any value that contains `{` or `}` before replacement.
   - English file is the template (`app_en.arb`, with `"@@locale": "en"`). For Arabic, use the `ar` value when present, otherwise the
     English value; print the list of keys that fell back.
   - Write both files pretty-printed, keys sorted alphabetically.
3. Run `dart run tool/strings2arb.dart` from `lavender-flutter/`. Expect ~414 keys. The fallback list should only be strings that are
   `translatable="false"` in English (which are skipped anyway) → ideally empty.
4. `l10n.yaml`:
   ```yaml
   arb-dir: lib/l10n
   template-arb-file: app_en.arb
   output-localization-file: app_localizations.dart
   output-dir: lib/l10n/generated
   synthetic-package: false
   nullable-getter: true
   ```
   Run `flutter gen-l10n`. Import as `package:lavender/l10n/generated/app_localizations.dart`.
5. `lib/app.dart`: add `localizationsDelegates: AppLocalizations.localizationsDelegates`, `supportedLocales: AppLocalizations.supportedLocales`,
   `locale: const Locale('ar')` (T10 replaces this with `SessionCubit.languageCode`). Show `context.l10n.appName` on the temporary home
   (check the key name in the generated file; Android `app_name`).
6. Tests (`test/tool/strings2arb_test.dart`): camelCase conversion incl. keyword suffix; placeholder conversion for `Good morning%s`,
   `(%1s/%2s) session`, `%s%%`; unescaping of `doctor\'s`; CDATA content kept.
7. Run the checks.

## Done when
- `dart run tool/strings2arb.dart` regenerates both ARB files with no errors (rerunning gives an identical diff).
- `flutter gen-l10n` succeeds; `flutter analyze` → no issues; `flutter test` → pass.
- App on emulator shows the Arabic app name, layout direction RTL (text aligned right). Temporarily change locale to `en` → English (revert after).

## Out of scope
- Saving/choosing the language (T06 storage, T10 session, T32 sheet). Fonts (T03).

## Gotchas
- Arabic is the default when nothing is stored (`getAppLanguage()` returns "ar"), not the device language.
- gen-l10n fails on unescaped `{`; the script must report them.
- Some Android strings start/end with spaces on purpose (e.g. greeting `Good morning%s` gets `", Name"` appended); do **not** trim inside the
  value beyond the outer XML whitespace. If a test shows trimming removes meaningful spaces, trim only newlines/indentation.
- Keep the script; it is the way to resync strings if the Android strings change.

- Deviations from the task file:
  - Keys starting with a digit (`_1`..`_5`): appending `Text` gives the still-invalid `1Text`, so the script prefixes `text` instead (`text1`..`text5`). Reserved words still get the `Text` suffix.
  - `synthetic-package: false` removed from `l10n.yaml` (deprecated, flagged by gen-l10n).
  - `app.dart` does not use `AppLocalizations.localizationsDelegates`: it references the deprecated `flutter_localizations` Material/Cupertino delegates (Flutter 3.47) and the app then fails with "MaterialLocalizations for ar not found". It lists `AppLocalizations.delegate` + `GlobalMaterialLocalizations` (material_ui) + `GlobalCupertinoLocalizations` (cupertino_ui, added as a direct dependency) + `GlobalWidgetsLocalizations` (flutter_localizations) explicitly. Later tasks that build another MaterialApp/test harness need the same list.
  - `lib/l10n/generated/**` is excluded in `analysis_options.yaml` (generated code uses the deprecated imports).
- Generated files are not hand-edited; rerun `dart run tool/strings2arb.dart && flutter gen-l10n` to resync. In widget tests, wrap with the same delegates / `locale`.
